# Equation Audit

This audit distinguishes the paper’s equations from the engineering choices required to run a small independent implementation. It follows the equations and interpretation supplied with this reproduction task; it is not a replacement for the paper.

## Eq. 1 — Iterative Feedback

Paper notation:

$$
o_t \sim \pi_\theta(o_t \mid s_t, R_t, f_t^i)
$$

Engineering timing used here:

$$
o_t \sim \pi_{\theta,t}(o_t \mid s_t, R_{<t}, f_{<t})
$$

The current action is generated before the current Checker score exists. `SageAgent` builds the prompt from prior feedback/reward, memory, and policy state, then calls the backend, parses the result, and invokes the Checker. This is a causal implementation choice for the paper’s underspecified timing.

Code: `src/sage/agents/agent.py`, `src/sage/agents/assistant.py`.

## Eqs. 2–3 — Self-Evolution

$$
G_{t+1} = (A_{t+1}, D_{t+1}), \qquad
\pi_{\theta,t+1} = \psi(\pi_{\theta,t}, G_{t+1})
$$

`EvolutionGoal` and `PolicyRevision` are structured engineering representations. The revision updates next-prompt instructions, corrective plan, and memory context; it does not update model parameters. No unique optimizer is attributed to the paper.

Code: `src/sage/core/types.py`, `src/sage/agents/agent.py`.

## Eqs. 4–5 — Reflection and Memory Insertion

$$
r_t = \mathrm{ref}(o_{1:t}, R_{1:t}), \qquad
M_L \leftarrow M_L \cup \{r_t\}
$$

The deterministic evidence-constrained generator converts interaction history and Checker evidence into a structured reflection. The validator checks schema and provenance before the record can enter the memory lifecycle. In full mode, MemorySyntax runs before STM/LTM management. Reflection is not generated by a language model in this project.

Code: `src/sage/reflection/generator.py`, `schema.py`, `validator.py`; `src/sage/memory/manager.py`.

## Eq. 6 — Forgetting Curve

$$
R(I_t, \tau) = \exp(-\tau/S)
$$

The implementation requires finite $\tau \ge 0$ and $S > 0$, supports seconds/minutes/hours/days, and clamps the result to $[0,1]$. Clock timestamps are stored in seconds; elapsed time is converted to each record’s configured strength unit.

Code: `src/sage/memory/forgetting.py`, `src/sage/core/clock.py`.

## Eq. 7 — MemorySyntax

The linguistic optimization is $I_t \rightarrow I_t^{&#42;}$. The implementation retains both original and optimized information, base strength $S$, optimized strength $S^{&#42;}$, current layer, active strength, and retention. While in STM, retention uses $S^{&#42;}$; after promotion, LTM starts a new decay epoch and uses base $S$.

The optimizer extracts facts, entities, constraints, errors, causes, corrections, reusable lessons, and evidence; it de-duplicates expressions and checks preserved content. The estimator and strength inheritance at promotion are engineering assumptions. Strength increases only after preservation validation and reduction of the lexical token proxy.

Code: `src/sage/memory/syntax.py`, `src/sage/core/types.py`, `src/sage/memory/manager.py`.

## Eq. 8 — Threshold Interpretation

The paper’s mathematical expression and prose description do not fully agree on the state transitions. This implementation follows the prose:

| Retention | Operation |
| --- | --- |
| $R \ge 0.7$ | Keep in STM |
| $0.3 \le R < 0.7$ | Promote to LTM |
| $R < 0.3$ | Mark forgotten and delete from searchable storage |

The inclusive boundary decisions $R=0.7$ and $R=0.3$, plus values immediately above and below, are tested.

Code: `src/sage/memory/manager.py`; lifecycle tests in `tests/unit/test_memory.py`.
